# 首次通用仓库提取计划

## 已确认范围

- 定位：供不同项目复用的 AI Agent 开发模板，README 标题为 Agent Development Harness。
- 独立目录与全新 Git 历史，默认主分支为 `main`。
- 保留通用需求、实施、独立评审、交付和知识维护流程。
- 默认中文协作；GitHub 状态机及固定 SHA 评审在接入远程后启用。
- 通用工程原则与项目运行模型分离；单维护者模型为可选示例。
- 首版环境为 Linux／WSL、Bash／GNU；离线自检独立于业务运行时。
- 通用能力集中维护，下游记录版本或 SHA，人工审阅更新。
- 用户后续授权：本地完成后发布至指定个人账号的公开仓库，并检查连接器访问。
- 首次发布不添加 LICENSE，许可证后续确定。

具体提取来源与文件映射由 [来源记录](../../docs/provenance.md) 维护。

## 验收标准

1. 通用流程、工具、模板和回归完整，保留原有通用约束。
2. 来源记录之外无原业务内容、固定账号、本机路径或业务环境依赖。
3. 文档、工具与模板引用有效，项目配置入口明确。
4. 干净检出在声明工具已安装时可执行离线检查，无需 GitHub 认证或业务服务。
5. 需求准入、非法状态转换、PR 契约与评审证据具备正反回归。
6. 来源 SHA、提取范围和验证结果可追溯，Git 历史独立，完成本地提交。

## 实施顺序

1. 固定来源 SHA，白名单提取。
2. 清除业务绑定，整理本地阶段与 GitHub 阶段。
3. 接通通用质量入口、模板检查和离线测试。
4. 验证并形成初始提交，在独立本地克隆中重跑检查。
5. 按用户授权创建远程、推送、读取仓库与提交，验证连接器和远程 CI。

## 验证方案

```bash
scripts/quality/check.sh --check-tools-only
scripts/quality/check.sh
scripts/quality/check_template.sh --source-audit
git diff --cached --check
```

首个提交后执行 `git show --format= --check HEAD`，并从独立本地克隆运行统一入口。
测试覆盖未确认需求、非法状态转换、缺少审计字段、远程模拟失败与读回不一致、
PR 结构与关联错误、评审阶段和结论冲突、工具缺失与版本错误，以及模板引用破坏。

## 证据边界

本地模拟验证脚本语义；真实 GitHub 访问、连接器和 CI 运行以发布后的读回为准。
自检与首次发布不标记为独立 R1–R3 评审。结果见
[首次验证记录](../../docs/reports/initial-validation.md)。
